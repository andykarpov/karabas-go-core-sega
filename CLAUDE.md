# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A Sega Mega Drive / Genesis core (68000, Z80, VDP 315-5313, YM2612 + SN76489, cartridges with the SSF2 mapper, save RAM / EEPROM, 3 / 6 button pads) for the Karabas Go, Mini and Mini G boards (Xilinx Spartan-6 XC6SLX25, ISE 14.7, XST): a port of [fpgagen](https://github.com/mist-devel/fpgagen) of MiST (commit a51ca7d; submodules fx68k 9fd1c83, T80 7126b13, jt12 7e66c41, jt89 5050cfc), with [Genesis_MiSTer](https://github.com/MiSTer-devel/Genesis_MiSTer) and [mdtang](https://github.com/nand2mario/mdtang) as donors.

Status (2026-11-11): phase 0 done (the Genesis alone without SVP: 11824 LUT = 78 %, 16 RAMB16; XST estimate SDR_CLK 119.8 MHz, MCLK 50.4 MHz with the worst path inside the T80, which runs on an enable every 15 MCLK: multicycle in the ucf of phase 2); phase 1 done (Verilator simulation, `src/sim/run_checks.sh` ~15 s after the build); phase 2 done (Mini G 26111101: timing met, 12754 LUT 84 %, 98 % slices; on the board Fantastic Dizzy and Earthworm Jim (Europe) run with pad and HDMI sound); phase 3 (saves, modes, keyboard) is next. Docs, in Russian: `docs/PLAN.md` (research, decisions, phases). Follow the phases; record a changed decision in PLAN.md. One branch + one PR per phase, merged at the end of the phase.

An earlier attempt by another tool (deepseek, archive `~/Downloads/Telegram Desktop/karabas-go-core-sega.zip`) is NOT the base: the core is written from scratch, only its lessons are taken (PLAN.md lists them).

User decisions (2026-11-11): base fpgagen MiST; **memory as on MiST**: ROM, 68K RAM, VRAM and save RAM in the SDRAM through fpgagen's own `sdram.sv` at 108 MHz; **the SRAM holds a frame buffer**; video output **1024 x 768 @ 60 Hz (65 MHz)**, 3x vertical, both H32 and H40 scaled to 960 wide; name `sega` (`sega.kg`, `/sega`), public repo. Clocks: one `kg_pll`, VCO 650 MHz (MCLK 54.17, SDRAM 108.3, video 65, TMDS 325). No SVP. All file work goes through the firmware (OSD, `FL` items, `kg_bk_ram` for `.sav`): no loader or soft CPU in the core. Game ROMs are user files: never in the repo or the `.kg`.

Templates: `../karabas-go-core-atarist` (fx68k through sv2v, SDRAM + SRAM, Makefile, Verilator harness), `../karabas-go-core-macplus` (1024 x 768 output, 48 kHz HDMI audio, `src/tools/mktops.py`), `../karabas-go-core-nes` / `../karabas-go-core-snes` (pads from `kg_mcu`, keyboard as pads, `.sav` through `kg_bk_ram`).

## Layout

- `docs/PLAN.md`: the plan.
- `src/make_core.py`: a symlink to `../../karabas-go-tools/make_core/make_core.py`.
- `modules/`: the git submodule [karabas-go-modules](https://github.com/andykarpov/karabas-go-modules). Clone with `--recursive`. A change to a module is made there (branch + PR) and taken here by moving the submodule commit.
- `src/rtl/fpgagen/` (upstream `src/`), `src/rtl/fx68k`, `src/rtl/T80`, `src/rtl/jt12`, `src/rtl/jt89` (commits in `src/rtl/UPSTREAM.md`): changes marked `karabas:`, listed in PLAN.md Ф0.
- `src/rtl/sv2v/` + `src/sega.prj`: generated by `src/tools/sv2v.sh` (in git; rerun after a source change). `sega.prj` = the Genesis alone (`fpgagen_sdram_top`, `USE_SVP` false through `sega.xst`); the SVP files are in it only because XST parses a false generate too.
- `src/sim/`: `build.sh` (the VHDL through `ghdl --synth --out=verilog`, fixed by `ghdl_relabel.py` / `ghdl_fixup.py` for ghdl 4.1 bugs, then Verilator with `sdram_model.v`, `sim_top.v`, the harness `sim_sega.cpp`), `mkrom.py` (the test ROM, no assembler), `run_checks.sh` (quick checks: frame size, band colours, PSG tone, SDRAM protocol), `run_rom.sh FILE` (games, ~4 s per frame: ask first). The harness options are in the header of `sim_sega.cpp`.
- `src/rtl/karabas_minig_top.v` (the board: clocks, kg_mcu, loader, pads, frame buffer, OSD, audio, HDMI; its header lists the clocks and the soft switches), `src/rtl/karabas/sega_loader.v`, `src/rtl/karabas/sega_fb.v`, `src/karabas_minig.ucf` (its timing part explains the FROM-TO and the T80 multicycle).
- `src/Makefile` (as core-macplus: `make minig`, `make sega-xst` / `sega-report` = the Genesis alone; BOARDS = minig until phase 4), `src/core.json`, `src/tools/check_osd.py`; `src/tools/sv2v.sh` also writes `karabas_minig.prj`.

## Rules of the core

The rules of core-atarist apply: standard video timing with syncs always present (the user's monitor rejects anything else), `FT_CLK_OUT` about 8 MHz on Mini / Mini G, Go `FDC_*` outputs 0 when unused, OSD switch index = item position unless `"index"`, an OSD value shows 10 characters at most, FL slots 0..7 only (one array with the F slots), Verilog-2001 for XST (`sv2v` for SV), imported code marked `// karabas:` / `-- karabas:`.

- Mini / Mini G tops drive T3 (`FLASH_CS_N`) = 0: on Mini G2 it is the SDRAM ~CS.
- Registers with no reset that leave their idle state only through a condition on themselves get trimmed by XST (works in sim, not on the board): give them an initial value and read the `.syr` for Xst:1710 / 2404.
- XST confuses a VHDL package with a Verilog module of the same name in a mixed design: rename such packages (`jt12_pkg`, `jt89_pkg`, `sdram_pkg`).
- No debug ports inside the imported RTL and no test bitstreams in git: diagnose in the simulation.
- Builds: map / PAR with cost table 2 first; no needless all-board PAR runs. Long sims (minutes) only after asking the user; start them with `job run` + Monitor on `job watch`.
- Board checks through the shared bench queue (`hwq`), ask before flashing. With the core running the CDC port resets about every 10 s (SDRAM activity, known): retry bench commands; the fileloader file is picked in the OSD browser (`key menu+esc`, up / down, enter), `mount` does not apply to it.
- `sdram.sv` registers the VRAM candidate (`karabas:`, needed for 108 MHz on the Spartan-6): keep it when updating from upstream.
